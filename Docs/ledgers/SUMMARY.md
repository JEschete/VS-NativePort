### Slices and retirement

[GATE_SLICES.csv](GATE_SLICES.csv) records migrated slices. The first is F01829,
`VS::Core::SortPointersByDescendingKey`, in the AI candidate ranking path: its old `void**` C ABI
and EC-04 original-address module symbol have zero consumers. That is one leaf function, not whole-AI
promotion or EC retirement; its callers remain C ABI, and generated `ActionPlanning.c` still drives it.
The second is the AI squared-distance slice, F01771-F01774 in `VS::Core::Math` (`Core/Math/Distance.hpp`):
callers pass `Position3` and `TileCoordinate` values instead of `short*` aliases, packed tile words and the
shared assembly entry's register inputs, and the four original-address module symbols are removed (no disc
module stores those addresses as data). Nine AI caller files, five of them generated, are adopted through
the copier; they remain C ABI functions, so this is four leaves, not AI promotion or EC-04 retirement.
The third is the AI terrain-height slice, F01759-F01764, F01767 and F01768 in `VS::Field`
(`Field/TerrainHeight.hpp`): queries take an explicit read-only `TerrainGrid` view, decoded tiles and
`Position3` endpoints instead of the hidden AI frame height map, packed tile words and `SVECTOR` pointers, so
the file compiles as strict C++ without the C SDK headers. AI callers fetch the frame grid through
`VS::Battle::Ai::CurrentTerrain`; the frame map itself is still a C struct field, so this is eight leaves.
The fourth is the AI room-map slice, F01837-F01839 in `VS::Battle::Ai` (`Battle/Ai/RoomAiMap.hpp`,
`Battle/Ai/TileHeightSampling.hpp`): `BuildRoomAiMap` is a pure function of an explicit `RoomAiSource`
(collision cells, a floor-height query, triggers and a bounded auxiliary span), and the room lifecycle
publishes and releases the result through a `RoomAiRuntime` interface. `BattleRoomAiRuntime` still binds the
map to the C AI frame globals that generated AI code reads, so this retires the inline `Field_roomData`
reads and the old C entry points, not the frame bindings.
The fifth is the AI flight-terrain slice, F01731, F01830 and F01843 in `VS::Battle::Ai`
(`Battle/Ai/FlightTerrain.hpp`): the lowest reachable ground takes a `FlightNeighborhood` (terrain grid, origin
tile, direction steps and a flight test called once per direction in order), the segment minimum takes the grid
and world positions, and the ceiling reads the published settings through `RoomAiRuntime`, instead of the AI frame
height map, the scratchpad direction table and `Battle_Ai_roomAiState`. Both module symbols retire (BATTLE.PRG
reaches them by `jal` only). `ActorFlightNeighborhood` still reads the frame terrain, direction table and the C
`Battle_Ai_CanFlyInDirection` cache, so the frame state stays C.
The sixth is the scalar math slice, 13 rows in `VS::Core::Math` (`Core/Math/ScalarMath.hpp`): the four Q12

`Angles3` and `SineCosine` values instead of MATRIX and VECTOR pointers or register pairs. `Apply*` adapters keep

### All native code compiles as C++ (owner decision, 2026-10-31)

`Native\` holds no `.c` file, assembly file or inline assembly, and `gates.py --check` fails if one returns. The 324
generated and 38 hand-written C sources compile as C++23. This is language migration, not promotion: they keep C
linkage and the relaxed settings, so their functions stay `wip` and none gains `cpp=x`, `modernized` or `verified`.

Generated files remain reproducible: `tools\port\cpp_adapt.py` derives the conversions C performed implicitly from
compiler diagnostics, `tools\port\cpp_adaptations.json` records them, and the copy tool replays them. Copied code keeps
C's meaning through `/J`, `-fno-finite-loops` and `-fno-strict-return`.
