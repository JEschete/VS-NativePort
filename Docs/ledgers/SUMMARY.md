### C++ promotion inventory

[CPP_PROMOTION.csv](CPP_PROMOTION.csv) holds one row per owned C++ function with one
column per [§8.2 step](../NATIVE_SOURCE_PORT_PLAN.md#82-promotion-checklist-c--cpp-sets-cpp--yes);
catalog `cpp` is derived from it. Per-file counts are in `build/quality/gates.md`.
`source_cpp` and `strict_clean` are measured. They hold for every owned C++ function,
which is why they say little on their own: the other four steps carry the promotion.

**Correction, not regression (#247):** 28 rows recorded `cpp=x` before this ledger: 23 audio
rows in `XaPlayback.cpp`, `SequencerOutput.cpp`, `MusicState.cpp` and `StreamPlayback.cpp`,
and 5 menu rows in `Menu/Sounds.cpp`. All were global C-ABI symbols with blank `modernized`,
in files including `Legacy/Psx.h`, so they failed §8.2 steps 2 and 4. They now read `wip`,
as does every other owned C++ function with an incomplete record.

**Limit:** a function with generated C callers cannot reach `cpp=x` until those callers
migrate, because generated C cannot call into a namespace. Most owned C++ functions are in that position.

### Behavior verification

[VERIFY_LEDGER.csv](VERIFY_LEDGER.csv) holds one record per verification. Every `verified=x` resolves
to a passing record whose test, replay or capture references exist. Migrated records rerun the
existing unit tests in Debug and Release; gameplay and device claims in catalog notes stay historical.
A record is a reference, not a fresh run.

**Explicit corrections (#249):** `verified=x` was removed from F02737, F02738, F03604 and F03605
(`Save::MemoryCard` menu resource lifecycle). No test, replay or committed capture exercises them;

## Inventory snapshots versus current status

The separate [native symbol review](NATIVE_SYMBOL_REVIEW.csv), completed for
#148 on 2026-10-27, records 570 individually justified binding/snapshot
retentions. It complements the existing function/field evidence; it does not
replace those ledgers or advance their status columns. Each record includes a
specific binding, rationale, source evidence, normalized-LF source SHA-256 and
exact identifier positions. Separate reviewed committed/dirty variants prevent
owner edits from being included in a naming commit or silently approved.

The expanded C/C++ inventory includes implementations, headers, modules and
inline/template bodies, including all 28 current `.inl` producers. On the final
dirty source snapshot, all 1,873 lexical occurrences in 362 file/name pairs
have explicit decisions; the committed snapshot has 1,871 occurrences/361 pairs.
This intentionally retains meaningful math/SDK names, unused formals,
declaration-only artifacts and specifically justified mixed/unknown roles.
It is not a claim that every short spelling or opaque field has a known meaning.
See [the exact commands and limits](../NAMING_CONVENTIONS.md#116-native-semantic-sweep-148-2026-10-27).

[SOURCE_FILE_LEDGER.md](SOURCE_FILE_LEDGER.md) and
[SDK_API_LEDGER.md](SDK_API_LEDGER.md) retain reference-inventory counts and
per-file/per-API gates. Their original-source counts and unchecked boxes are
not automatically synchronized with native ownership or issue acceptance.

by the persisted-ledger counts above.

For a read-only recount in PowerShell:

```powershell
$functions = Import-Csv Docs\ledgers\FUNCTION_CATALOG.csv
$functions.Count
$functions | Group-Object copy | Select-Object Name, Count
foreach ($column in 'copied','compiles','named','understood','modernized','cpp','verified') {
    $column
    $functions | Group-Object $column | Select-Object Name, Count
}
foreach ($ledger in 'DATA','TYPE','FIELD') {
    $rows = Import-Csv "Docs\ledgers\${ledger}_LEDGER.csv"
    "$ledger rows: $($rows.Count)"
}
$owned = Import-Csv tools\port\owned.csv
$owned.Count
@($owned.path + $owned.header | Where-Object { $_ } | Sort-Object -Unique).Count
.\.venv-3\Scripts\python.exe tools\ledger\gates.py --check
```
