# Modernization tracker

The work between "compiles as C++" and "is modern C++", tracked per function so that none of it depends on memory. Compiling
as C++ was the language migration. It kept C linkage, raw pointers and relaxed settings, so almost all of the promotion
work in [plan section 8.2](NATIVE_SOURCE_PORT_PLAN.md#82-promotion-checklist-c--cpp-sets-cpp--yes) is still ahead.

[MODERNIZATION_LEDGER.csv](ledgers/MODERNIZATION_LEDGER.csv) has one row per port target. Roadmap issues in #217 describe
architecture changes rather than per-function work, so this ledger is what tracks each function through them.

## Reading the ledger

| Column | Meaning |
| --- | --- |
| `track` | `owned`: hand-maintained. `generated`: still produced by the copy tool, so it must be taken over first |
| `status` | `todo`, `in-progress`, `blocked` or `done`. Hand-written, as is `notes` |
| `issue`, `imp_step` | The roadmap issue and step this function's work belongs to. `none` means no issue covers it yet |
| `compile` | Measured: `strict` or `relaxed`. `unbuilt` means the catalog names a file that is not compiled |
| `body` | Where the code is: `found`, `alias:<target>`, `template:<macro>`, `instance:<macro>` or `missing` |
| `source_cpp` to `behavior_evidence` | Copied from [CPP_PROMOTION.csv](ledgers/CPP_PROMOTION.csv), which stays the authority |
| `generated_consumers`, `hand_consumers`, `test_consumers` | Source files naming this function |
| `module_table` | Also referenced by the original-address table in `ModulePointers.cpp` |
| `legacy_calls`, `legacy_signature` | SDK shims it calls, and whether its signature uses SDK integer types or `void*` |
| `source_flags` | Original-code traits from the catalog, such as `scratchpad` or `inline_asm` |
| `tests_execute`, `replay_execute`, `region_pct` | Measured coverage from `regression.py coverage` |
| `regression` | `recorded`, `executed`, `characterize-first` or `unmeasured` |

Consumer and blocker columns describe the last `--sync`, so ordinary edits do not fail the check. A row that moved, appeared or
disappeared does. Platform hazards are tracked per site in [PLATFORM_HAZARDS.md](PLATFORM_HAZARDS.md) and join on `id`.

## Working a slice

Work in slices rather than one function at a time, because a function with generated callers cannot reach `cpp=x` until those
callers migrate. A template and all of its instances are also one piece of work.

[PROMOTION_PLAN.csv](ledgers/PROMOTION_PLAN.csv) is the slice queue. Each row names the files one slice promotes, in roadmap
order, with its `status` (`planned`, `active`, `blocked` or `done`), its `owner` (`coordinator`, or `agent:<name>` for a delegated
worktree), and, once finished, its `GATE_SLICES.csv` record and commits. `modernization.py --check` refuses an open function
whose file is in no slice, a file in two slices, a `done` slice with open functions or no gate record, a slice whose files have
nothing left but which is not marked `done`, and more than two active `agent:` slices. The tracker block above shows what each
slice has left.

1. **Pick a slice**: the lowest-order `planned` row of the plan. Set it `active` with its owner. Move callers and callees
   together where you can.
2. **Check its cover.** If `regression` says `characterize-first`, write tests that pin today's behavior and watch them pass on
   the unchanged code. Then rerun `regression.py coverage`.
3. **Set `status` to `in-progress`.** The check refuses this while `regression` is `characterize-first` or `unmeasured`.
4. **Take ownership** of generated functions with `tools\port\own.py`.
5. **Clear its hazards** from [HAZARD_LEDGER.csv](ledgers/HAZARD_LEDGER.csv), and do the section 8.2 steps.
6. **Run `regression.py check`** in Debug and Release. The result must match the baseline.
7. **Record the evidence** in `VERIFY_LEDGER.csv` and `CPP_PROMOTION.csv`, then set `status` to `done`. Mark the plan row
   `done` with its `gate_slice` and commits.

## Regression testing

`tools\test\regression.py` compares each run with [regression_baseline.json](../tools/test/regression_baseline.json).

| Layer | What it catches | Where it runs |
| --- | --- | --- |
| Test names | A test deleted or renamed | CI, from source, no build needed |
| Full test run | A failing or skipped test, or a falling assertion total | Locally: `regression.py check` |
| Scenario replays | Any change in per-tick game state, named by frame window | Locally, needs the converted game data |
| Coverage | A function that was running and no longer is | Locally: `regression.py coverage` |
| Ledger check | Starting work with no cover, or `done` without promotion | CI |

Recording a new baseline is a deliberate, reviewable act, because its diff is the behavior someone chose to give up.

### Why replays step the frame counter

Two identical runs of the same scenario used to diverge within about two seconds. `Core_ElapsedFrameCounterTicks` reads the real
clock, and `lastBudgetTick` feeds that value into the AI's random state in `Battle_Ai_NextActorRandomMasked`.
On the PS1 this was a hardware counter. With `--fixed-frame-ticks 7`, each read since the frame began advances by 7 units instead,
and two runs match on every field of all 2,400 frames. Normal play is unchanged.

The step is deliberately not zero: a constant would freeze the AI's random state and quietly test less behavior. It is odd because
the AI masks that state with a power of two. Replays do not exercise the path that stops AI work when a real frame runs long.

## Known gaps

- **CI does not build or run the tests.** It only checks source. A change can pass CI and still fail `regression.py check`,
  so that command has to be run before merging. Adding a build job is open work.
- **Replays cover what their scenarios reach.** Menus, events and most effects need their own scenarios. Carrying a box has no
  replay yet: #252 is covered by unit tests, and a scripted lift did not succeed, so that scenario should come from recorded input.
- **`--press` cannot express analog input,** so a real play session cannot be replayed as it stands. Recording pad input would
  turn any playtest into a regression test.
- **Coverage shows a function ran, not that its result was checked.**
- **The roadmap mapping is proposed,** from each path's system and each issue's title.
